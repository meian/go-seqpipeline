# 測定条件と読み方

## 数値の読み方

| 表示 | 意味 |
| --- | --- |
| ns/op | 1 回の処理時間。中央値 |
| B/op | 1 回の割り当てバイト数。保持メモリ量とは異なる |
| allocs/op | 1 回の割り当て回数 |
| ± | 中央値の 95% 信頼区間の相対幅 |
| 倍率 | 時間比較の右列 / 左列。1 より大きいと右列が遅い |
| 検定の増減率 | 時間比較の左列を基準にした右列の増減 |
| ~ | 有意水準 0.05 で差が不明確 |

単一環境での整数処理の結果であり、外部 I/O や他の型でも同じ倍率になるとは限らない。  

## API 別結果（Unit）

入力は 64 / 4096 件の整数で、入力データの準備を除き、入力 iterator の生成・API 呼び出し・評価・収集を含む。  
Go は標準ライブラリや直接のループによる同一処理、Library は各 API を使った処理全体を測る。  
各 API の比較表に Go の書き方を示し、入力・出力・収集・結果保持の範囲をそろえている。  
部分スライスを使える Take / Skip も、その通常の書き方と比較する。  

| 条件 | 対象範囲 |
| --- | --- |
| 構築・評価 | 接続・全件反復・値の加算 |
| 収集 | スライス / map の生成・全件収集・値の加算 |
| Channel | 容量 0・1 goroutine の生成・全送受信・終了・値の加算 |
| 先頭8件 | Take の接続から先頭 8 件の反復・加算まで |
| Fill | Cache / Cache2 の呼び出しと全件保存。保存後の反復は含まない |
| Warm | 保存済み結果の全件反復・加算。保存費用は含まない |

Map は値に 1 を加算し、Filter は 3 の倍数を除き、Skip は先頭 8 件を除外する。  
Seq2 のキーはスライスの添字で、Keys / Values はキー / 値を取り出す。  
Zip の既定ケースは等長入力、補完設定のケースは片側を半分の件数にし、出力はいずれも N 件とする。  
Pipe / Pipe2 は Seq では Map / Zip、Seq2 では Values / Map2 を接続した費用を含む。  
設定・型変換も反復まで含むため、呼び出し単独の費用ではない。  

## 利用場面別結果（Scenario）

同じ行の対照とライブラリ実装は、入力・処理・出力と計測範囲をそろえている。  

| 場面 | 入力・処理 | 計測範囲 |
| --- | --- | --- |
| Pipeline | 64 / 4096 件、Map 1 / 5 回と Filter。全件または Filter 後 8 件で停止 | 構築・評価・整数 2 個の組をスライスへ収集 |
| Channel | 64 / 4096 件、Map 1 回と Filter、全件を収集 | channel 生成・goroutine 起動・全送受信・終了・変換・整数 2 個の組をスライスへ収集 |
| Cache | 64 / 4096 件、整数変換を要素ごとに 0 / 32 回。全件を加算 | Fill / Warm / 保存費用込みの 1・4・16 回利用を分離 |

Pipeline の段数は Map と Filter の合計で、途中終了時の Take は別に加わる。  
Loop は直接ループ、Functions は要素ごとの通常の関数呼び出し、Pipeline はオペレーターの接続で同じ結果を作る。  
入力生成は計測に含まず、通常のインライン化・最適化は有効にしている。  

Channel の入力容量は 0 / 64、ToChannel の出力容量は常に 0。  
Direct / FromChannel / ToChannel は送信用 1 goroutine、RoundTrip は 2 goroutine を使う。  
途中終了・キャンセルの費用はこの Channel 比較に含まない。  

Cache の負荷 0 は軽い上流、32 は整数の乗算・加算を繰り返す上流を表す。  
同じ利用回数の Uncached / Cached は初回保存も含む合計時間で、保存済みの反復だけの Warm とは区別する。  
保持する値データは 1 件につき Seq が 8 bytes、Seq2 がキーを含め 16 bytes で、余剰容量等は別に必要になる。
