# Architecture Decision Records

このディレクトリには、開発者が後から判断と理由を確認できるよう、長く適用する意思決定を記録する。  
現在有効な判断は [current-decisions.md](current-decisions.md) から確認する。  

## 記録する判断

複数の妥当な選択肢があり、後の変更にも影響するパッケージの責務、公開契約、互換性、文書や開発運用の方針を対象にする。  
局所的な実装方法、軽微な修正、既存方針に従うだけの選択は ADR にしない。  
1 つの意思決定につき 1 つの ADR を作り、異なる判断を 1 ファイルにまとめない。  

## ファイルと書式

ファイル名は `0001-operator-package.md` のように、未使用の 4 桁の連番と小文字の英数字・ハイフンによる短い名前で付ける。  
番号は再利用せず、タイトルは `# ADR-0001: オペレーターを op パッケージに配置する` のように判断を表す。  
`採用` は ADR を含む変更が `main` に取り込まれてから有効になる。  
本文には次の項目を置く。  

- 決定日（`YYYY-MM-DD`）、状態（`採用`・`置換済み`・`撤回`）
- 背景、決定、理由、採用しなかった選択肢、影響、関連 ADR
- 判断の根拠となる Issue・PR・既存文書へのリンク

既存の判断を遡って記録する場合は、決定日と理由の根拠を示し、確認できない当時の議論を補わない。  
ADR は現在の詳細仕様を複製せず、必要な文書へリンクする。  

## 変更と優先関係

判断を置き換える場合は新しい ADR を作り、元の ADR を `置換済み` にして相互にリンクする。  
元の ADR の「関連 ADR」には後継を、新しい ADR には置換元を記す。  
判断を撤回して後継の判断を設けない場合は、元の ADR を `撤回` にし、理由と日付を記す。  
一部だけ変更する場合は元の ADR を残し、新しい ADR に変更範囲と元の ADR との関係を明記する。  
この場合は元の ADR にも新しい ADR へのリンクを加え、サマリでは両者が有効な範囲を分けて示す。  
同じ範囲に複数の ADR が関わるときは明示した適用範囲と関係で判断し、番号や日付だけで優先順位を決めない。  
関係が不明なまま判断が衝突した場合は、ユーザーに確認してから ADR とサマリを整える。  
判断の解釈を明確にする修正は元の ADR に経緯を残し、判断そのものを変える修正は新しい ADR に記す。  

## サマリと PR の確認

ADR の追加・変更・撤回時は、同じ PR で [current-decisions.md](current-decisions.md) を更新する。  
サマリには現在有効な判断、適用範囲、根拠となる ADR へのリンクを記し、失効した判断を現在の判断として残さない。  
PR では変更した ADR ごとに、サマリの判断文・適用範囲・リンク・状態と、関連 ADR との関係を照合し、確認結果を PR 本文に記す。
