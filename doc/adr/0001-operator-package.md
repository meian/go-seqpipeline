# ADR-0001: オペレーターを op パッケージに分離する

- 決定日: 2026-10-21
- 状態: 採用
- 日付の根拠: [Issue #48](https://github.com/meian/go-seqpipeline/issues/48) の完了日

## 背景

シーケンスの基盤とオペレーターを `seq` に集め続けると、役割の違う API が混在し、機能の配置先が分かりにくくなる。  
この ADR は、完了済みの Issue #48 と現在のパッケージ構成から判断を遡って記録する。  

## 決定

`seq` は `Seq` / `Seq2`、接続、入出力変換を扱い、オペレーターの型・実装・設定は `op` に置く。  
`op` は `iter.Seq` / `iter.Seq2` を入出力とし、`seq` に依存させない。  
依存方向を `seq → op → iter` とする。  

## 理由

機能追加時の配置先が明確になり、`seq` に異なる責務の公開 API が集中しない。  
`iter` を境界に使うことで、オペレーターを `seq` から独立させられる。  

## 採用しなかった選択肢

既存の判断を記録するにあたり、次の構成と比較した。  

- オペレーターを `seq` に置き続ける案: API の集中と責務の混在が残る

## 影響

新しいオペレーターは `op` に追加し、`seq` はその接続を担う。  
具体的な配置とテストの方針は [AGENTS.md](../../AGENTS.md) を参照する。
