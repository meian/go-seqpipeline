# `FromRange` の実装方針

`seq.FromRange` は整数の範囲を遅延生成する入力関数として実装する。  
公開契約と、その契約を満たすための実装上の判断を以下に定める。  

## 公開契約

- `start` と `stop` は同じ整数型 `T` とし、組み込みの符号付き・符号なし整数型と、それらを基底型とする定義型を受け付ける
- `uintptr` を対象に含め、`byte` と `rune` はそれぞれ `uint8` と `int32` の別名として利用できる
- 浮動小数点型は対象に含めない
- 引数順は `FromRange(start, stop, step)` とし、返り値は `Seq[T]`、`step` は環境によらず符号付きの `int64` とする
- `int64` で表せない増減値は指定できない
- `step` が正なら昇順、負なら降順とし、方向が合う場合は `start` と到達した `stop` を含める
- `stop` を飛び越す前に終了する
- `start == stop` かつ `step != 0` なら `start` を 1 件返す
- `step == 0` は関数呼び出し時に panic する
- `step` の符号が `start` から `stop` への方向と逆なら、空の非 nil `Seq` を返す
- 要素の生成は反復時に行い、各反復は `start` から独立して始める
- `yield` が `false` を返したら直ちに停止する
- 整数型の上限・下限を超えて折り返さずに終了し、`step == math.MinInt64` も同じ契約で扱う

## 実装構成

- 公開入口では `step == 0` を検査し、単一の反復関数を返す
- `rangeSteps` は反復開始時に向きと終点までの遷移回数を求め、方向不一致なら要素を返さない
- 現在値と残りの遷移回数を反復ごとのローカル状態に置き、途中停止後の再評価に影響を残さない
- 符号付き・符号なし、昇順・降順を共通の反復ループで処理し、型判定や反射は行わない
- `yield` が `false` を返した場合と、残りの遷移回数が 0 の場合は、次の値を計算せず終了する
- 空結果でも呼び出し可能な非 nil の `Seq` を返す

## 整数の表現と境界

方向の比較は元の型 `T` で行う。  
昇順の距離は `uint64(stop) - uint64(start)`、降順はその逆の差で求める。  
負数を含む符号付き整数も `uint64` への変換と減算を通すと、2^64 を法とする演算になる。  
方向確認後の数学的な距離は 0 以上 2^64−1 以下なので、この差と一致する。  
符号ビットの反転や、型ごとの処理分岐は必要ない。  

遷移回数は距離を `step` の大きさで割った商とする。  
要素数を加算しないため、全幅の `int64`・`uint64` を刻み幅 1 で生成する最大 2^64 要素の範囲も扱える。  
負の `step` の大きさは `uint64(-(step + 1)) + 1` で求め、`math.MinInt64` の符号反転を避ける。  

次の値は `T(uint64(current) + uint64(step))` で求める。  
残りの遷移回数が正のときだけ更新するため、数学的な次の値は必ず両端点の間にあり、元の型に収まる。  
負の増減幅や符号境界も剰余演算で扱い、`T` へ戻すことで定義型を保つ。  

## 方式を選んだ根拠

従来の比較では、11 型別関数と signed / unsigned の 2 関数、それぞれの `type switch` と `reflect` による分岐を調べた。  
Go 1.27.3・Apple M4・`step` の大きさ 1 の条件では、2 関数が一部の型と長い反復で有利であり、型判定方法の差は小さかった。  
ただし、いずれも生成と消費を合わせた割り当てが 3 回あり、生成済みシーケンスの再利用は比較していなかった。  

現在の構成は、公開入口から単一の反復関数を返し、向きと距離の計算を別関数へ出すことで、呼び出し元が生成側の実体を追えるようにする。  
要素ごとの処理を値の出力・更新と残回数の判定に絞り、通常の最適化で間接呼び出しと割り当ての削減を図る。  
インライン化を強制・抑制する指示や専用ビルド設定には依存しない。  
前処理は再利用時も反復の開始ごとに行うため、短い列ではその費用も含めて比較する。  

性能を確認するときは最終実装で短い列と長い列、昇順と降順、生成ごとの評価と生成済み `Seq` の再利用を分けて測る。  
`ns/op`・`B/op`・`allocs/op` を記録し、測定順を逆にしても差が再現するか確認する。  
測定環境・コマンド・測定時間・回数と比較結果は対応する Issue・PR に記録し、公開レポートへの反映は定期更新で行う。  

## 検証と文書

`seq` の単体テストで端点への到達・飛越し、終点から遠ざかる `step`、0、狭い整数型を超える `step`、最大・最小値、定義型、再評価を確認する。  
狭い整数型は十分な幅の独立計算と照合し、全幅の範囲は先頭の生成と停止・再評価を確認する。  
`Pipe`・収集・途中停止の連携は単体テストと分けて検証する。
