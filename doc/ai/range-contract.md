# Issue #30: 数値 Seq の仕様境界

この文書は [Issue #30](https://github.com/meian/go-seqpipeline/issues/30) の公開契約を決めるための提案であり、現時点の確定仕様ではない。  
初期値・増減値・ストップ値から `Seq` を遅延生成し、途中停止と `Pipe`・収集関数への接続を可能にすることが Issue の目的である。  
API 名、引数順、対象型、端点と異常値の扱いは Issue で未決定とされている。  

## 既存 API との接続に必要な条件

- `seq` の入力生成関数として提供し、`op` のオペレーターにはしない
- 構築時に要素を生成せず、反復ごとに初期値から始める
- 下流の `yield` が `false` を返したら直ちに停止する
- 空結果でも非 nil の `Seq` を返す

最後の条件は現行の `seq` では nil の `Seq` を直接反復したり `ToSlice` に渡したりすると panic するために必要である。  
空の非 nil `Seq` を `ToSlice` に渡した結果は nil slice になる。  

## 公開前に決める契約

| 論点 | 初回の提案 | 明示すべき境界 |
| --- | --- | --- |
| API 名と引数順 | `Range(start, stop, step)` | `FromRange` との命名差、引数の意味 |
| 対象型 | `int` / `uint` と固定幅整数、およびそれらの定義型 | `uintptr` を含めるか。`byte` / `rune` は `uint8` / `int32` の別名 |
| 浮動小数点 | 初回は対象外 | 丸め、NaN、無限大、加算しても値が進まない場合は別の契約が必要 |
| `step` | `int` とし、負値で降順を表す | `uint64` などでは表せない大きさの増減があり、幅は実行環境の `int` に依存 |
| 端点 | 方向が一致する場合は `start` と到達した `stop` を含む | `stop` を飛び越す場合は直前で終了 |
| `start == stop` | `step != 0` なら 1 件 | 方向にかかわらず初期値を返す |
| `step == 0` | 関数呼び出し時に panic | 返り値に error を含めない場合の失敗時点とメッセージ |
| 方向不一致 | 空の非 nil `Seq` | 昇順に負の `step`、降順に正の `step` |
| 数値の限界 | 加算・減算の前に終了を判定する | 型の範囲を超えて折り返さず、`step == math.MinInt` も扱う |
| 再評価 | 毎回 `start` から独立して反復する | 途中停止後の再実行を含む |

`int` の `step` は符号なしの値を降順に生成できる一方、任意の `uint64` 間隔を 1 回の増減として指定できない。  
この制限を受け入れるか、`step` の型を変えるかは公開前に決める。  
Go の整数演算はオーバーフロー時に panic しないため、折り返し前の終了判定を実装とテストの両方で確認する。  

## 契約確定後の置き場所

公開 API に長く影響する選択の理由は `doc/adr/` の判断として記録し、[現在有効な判断](../adr/current-decisions.md) に反映する。  
個別の境界条件は GoDoc と `seq` の単体テストに置き、利用時に注意が必要な条件だけ日英の利用ガイドへ載せる。  
この提案文書は採用済み ADR や GoDoc の代わりにはしない。
