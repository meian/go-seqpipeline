# Issue #30: 数値 Seq の仕様境界

この文書は [Issue #30](https://github.com/meian/go-seqpipeline/issues/30) と [ドラフト PR #74](https://github.com/meian/go-seqpipeline/pull/74) のコメントを反映した公開契約の整理である。  
初期値・増減値・ストップ値から `Seq` を遅延生成し、途中停止と `Pipe`・収集関数への接続を可能にすることが Issue の目的である。  
Issue では API 名、引数順、対象型、端点と異常値の扱いが未決定だった。  
以下はレビューで選んだ方針を記録し、終点から遠ざかる `step` の扱いだけは説明後の確認を待つ。  

## 既存 API との接続に必要な条件

- `seq` の入力生成関数として提供し、`op` のオペレーターにはしない
- 構築時に要素を生成せず、反復ごとに初期値から始める
- 下流の `yield` が `false` を返したら直ちに停止する
- 空結果でも非 nil の `Seq` を返す

最後の条件は現行の `seq` では nil の `Seq` を直接反復したり `ToSlice` に渡したりすると panic するために必要である。  
空の非 nil `Seq` を `ToSlice` に渡した結果は nil slice になる。  

## 公開契約の整理

| 論点 | 方針 | 境界 |
| --- | --- | --- |
| API | `FromRange(start, stop, step)` | `start` と `stop` は同じ型、`step` は `int` |
| 対象型 | 組み込み整数型とその定義型 | `uintptr` を含む |
| 別名 | `byte` / `rune` を個別に列挙しない | `uint8` / `int32` の別名として利用できる |
| 浮動小数点 | 対象外 | 丸め、NaN、無限大の終了規則を設けない |
| `step` | `int` とし、符号で昇順・降順を決める | `int` の幅は 32 または 64 bit。表せない増減値は指定できない |
| 端点 | 方向が一致する場合は `start` と到達した `stop` を含む | `stop` を飛び越す場合は直前で終了 |
| `start == stop` | `step != 0` なら 1 件 | 方向にかかわらず初期値を返す |
| `step == 0` | 関数呼び出し時に panic | 空結果の場合も同じ |
| 終点から遠ざかる `step` | 空の非 nil `Seq` を返す案 | `start < stop` で負、`start > stop` で正の場合。要確認 |
| 数値の限界 | 加算・減算の前に終了を判定する | 型の範囲を超えて折り返さず、`step == math.MinInt` も扱う |
| 再評価 | 毎回 `start` から独立して反復する | 途中停止後の再実行を含む |

`uintptr` は `uint` の別名ではなく、独立した組み込み整数型である（[Go 言語仕様](https://go.dev/ref/spec#Numeric_types)）。  
`byte` と `rune` はそれぞれ `uint8` と `int32` の別名なので、個別の分岐は設けず、それぞれの元の型として利用できる。  
`step int` では符号なしの値も降順に生成できる一方、`MaxInt` を超える正の増減値は指定できない。  
この制限は受け入れる。  
「終点から遠ざかる」とは、`step` が決める方向と `start` から `stop` への方向が逆であることを指す。  
例えば `FromRange(1, 5, -1)` は初期値から終点へ進まないため、空のシーケンスを返す案としている。  
Go の整数演算はオーバーフロー時に panic しないため、折り返し前の終了判定を実装とテストの両方で確認する。  

## 契約確定後の置き場所

公開 API に長く影響する選択の理由は `doc/adr/` の判断として記録し、[現在有効な判断](../adr/current-decisions.md) に反映する。  
個別の境界条件は GoDoc と `seq` の単体テストに置き、利用時に注意が必要な条件だけ日英の利用ガイドへ載せる。  
この文書は採用済み ADR や GoDoc の代わりにはしない。
